## Пользователи и их задачи

| Пользователь | Что хочет сделать | Зачем |
|---|---|---|
| Владелец ЭМ в городе | Найти свободную зарядку рядом | Не тратить время на поиски |
| Оператор такси | Планировать маршруты смены | Избежать простоя машин |
| Администрация Уфы | Увидеть приоритетные площадки | Эффективно распределить бюджет |

## Функциональные требования

| ID | Требование | Источник | Эпик | Приоритет (MoSCoW) |
|---|---|---|---|---|
| FR-01 | Сервис должен рассчитывать интегральный показатель спроса на зарядку для каждой площадки на основе плотности электромобилей, транспортных потоков и POI-притяжения (ТЦ, ЖК, офисы) | Устав п.1 от 03.10.2026 / Интервью от 07.10.2026 | E2 | Must |
| FR-02 |Сервис должен рассчитывать показатель существующего предложения (число и мощность уже размещённых зарядных станций) в радиусе площадки и формировать приоритет = f(спрос, −предложение) | Интервью от 07.10.2026 | E2 | Must |
| FR-03 | Сервис должен отображать интерактивную карту Уфы с площадками, окрашенными по приоритету, и карточкой площадки (балл спроса, балл предложения, итоговый приоритет, адрес) | Устав п.3 от 03.10.2026 | E3 | Must |
| FR-04 | Пользователь может фильтровать список площадок по типу локации (город/трасса), по минимальному приоритету и по радиусу/району | Устав п.3 от 03.10.2026 | E5 | Should |
| FR-05 | Сервис экспортирует приоритизированный список площадок в CSV с полями: адрес, координаты, балл спроса, балл предложения, итоговый приоритет | Устав п.10 от 03.10.2026 / Интервью от 07.10.2026 | E4 | Could |

## Нефункциональные требования

| ID | Категория | Требование (измеримо) | Как проверим |
|---|---|---|---|
| NFR-01 | Производительность | Время расчёта приоритетов и отрисовки карты для полного набора площадок Уфы | <= 10 сек на ноутбуке с 8 ГБ RAM, замер 3 прогона, берётся медиана |
| NFR-02 | Удобство использования | Новый пользователь без инструкции находит топ-5 площадок и открывает карточку площадки | >= 80% из 5 тестовых пользователей справляются за <= 2 мин; SUS-оценка >= 70 |
| NFR-03 | Совместимость | Работа в актуальных версиях браузеров | Chrome, Firefox, Edge последних 2 мажорных версий; карта и фильтры функционируют без ошибок в консоли |
| NFR-04 | Воспроизводимость | Повторный запуск расчёта на тех же входных данных даёт идентичный результат | Совпадение ранжированного списка топ-20 и всех баллов (допуск +- 0.01) в 3 из 3 прогонов; версии датасета и параметров фиксируются в логе |
| NFR-05 | Ограничения окружения | Работа только на бесплатных сервисах и локальных вычислениях | 0 платных API/подписок в зависимостях; расчёт выполняется локально, без внешних платных вычислительных ресурсов |

## Требования к данным

| ID | Требование | Порог | Как проверим |
|---|---|---|---|
| DR-01 | Полнота | >= 90% площадок-кандидатов из согласованного перечня районов Уфы имеют заполненные координаты и адрес | Отчёт о покрытии: доля площадок с заполненными координатами и адресом >= 90%; список пропусков приложен |
| DR-02 | Точность положения | >= 90% проверенных точек (18 из 20) находятся в пределах 50 м от фактического адреса | Выборочная проверка 20 точек: >= 18 (90%) в пределах 50 м от фактического адреса |
| DR-03 | Актуальность | Дата выгрузки данных о существующих станциях и спросе <= 12 месяцев на дату расчёта | В метаданных датасета указана дата выгрузки <= 12 мес.; при превышении - требование помечается как невыполненное в отчёте |
| DR-04 | Лицензия и указание авторства | 100% источников имеют лицензию, допускающую использование и публикацию производных результатов (например, OpenStreetMap ODbL, открытые данные госорганов) | Для каждого источника в реестре данных указана лицензия и ссылка; ни один источник не запрещает производные результаты |

## Карта историй и MVP

| | Шаг пользователя 1: Сбор данных | Шаг 2: Расчет спроса | Шаг 3: Просмотр и экспорт |
|---|---|---|---|
| **MVP** | Загрузка базовых данных о населении и текущих ЭЗС | Расчет спроса по 4 базовым факторам (население, трафик, ЭЗС, сеть) | Карта с отображением 30 приоритетных площадок |
| | | | Фильтрация площадок по району и приоритету |
| **Следующие версии** | Интеграция с текущими данными о пробках | Модель машинного обучения для прогноза спроса | Мобильное приложение |
| | Учет маршрутов конкретных водителей | Учет сезонности | Интеграция с операторами для оплаты прямо на карте |

Обоснование границы MVP: проверяет гипотезу о том, что на основе открытых данных (население, трафик, текущие станции) можно построить карту, которая покажет 30 реальных мест, где строительство новых зарядных станций принесет максимальную пользу.

## Вне рамок продукта

- Мобильное приложение
- Мониторинг исправности станций в реальном времени
- Физическое строительство станций
