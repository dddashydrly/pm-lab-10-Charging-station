# План управления качеством

Версия: 1.0 · Дата: 14.11.2026 · Ответственный за качество: Анна П.

## 1. Что для нас качество
Требования к качеству, которые важны заказчику (Администрации Уфы):
- **NFR-01 (Производительность):** Карта должна открываться быстрее чем за 3 секунды на мобильном интернете.
- **NFR-03 (Правовые):** На карте всегда должна быть видна подпись «© участники OpenStreetMap».
- **NFR-04 (Воспроизводимость):** Весь расчёт (от загрузки данных до вывода карты) должен повторяться по инструкции за 15 минут.
- **Критерий приёмки:** Список приоритетных площадок должен содержать не менее 30 точек с обоснованиями.

## 3. Стратегия тестирования

| Уровень | Что проверяем | Инструмент | Автоматически? | Где результат |
|---|---|---|---|---|
| Проверка данных | Структура слоёв: CRS, геометрия, дубликаты, границы | `scripts/validate_data.py` | Да, в CI | Вкладка Actions (CI) |
| Модульные тесты | Функции расчёта (буферы, расстояния, доли) | `pytest`, `tests/` | Да, в CI | Вкладка Actions (CI) |
| Приёмка историй | Критерии «Дано / Когда / Тогда» | Ревью и обзор спринта | Нет | Обзор спринта |
| Проверка выводов | Цифры в отчете совпадают с ноутбуком | Второй участник перепроверяет | Нет | Протокол обзора |

**Что не тестируем и почему:** Сами ноутбуки (`.ipynb`) целиком в CI не запускаются, так как они требуют Google Диска и доступа в интернет. Вместо этого расчётные функции вынесены в `src/`, и тесты проверяют их. 

## 4. Чек-лист ревью Pull Request

**Для любого PR**
- [ ] PR связан с задачей (`Closes #N`), ветка названа по правилам.
- [ ] Автопроверка `ci / quality` зелёная.
- [ ] Нет пустых разделов и пометок TODO.

**Код и ноутбуки**
- [ ] Расстояния и площади считаются в метрической проекции (не в градусах).
- [ ] Ноутбуки сохранены без вывода ячеек.
- [ ] У новой расчётной функции есть тест с известным ответом.

**Данные**
- [ ] Источник и лицензия записаны в `data/sources.md`.
- [ ] Новые фильтры данных объяснены в коде или в `docs/data-quality.md`.

**Документы**
- [ ] Выводы сформулированы «по данным OSM», а не как абсолютный факт.
- [ ] Использование ИИ записано в `docs/ai-usage.md`.

## 5. Качество в Definition of Done
В `docs/definition-of-done.md` добавлены следующие пункты:
