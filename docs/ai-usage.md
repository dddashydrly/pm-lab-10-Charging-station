```text
Ты аналитик требований в IT-проекте. Наш проект: создание сервиса с приоритизированным списком площадок для размещения зарядных станций электромобилей в Уфе

Заказчик - Администрация Уфы (нужно понять, где строить станции)
Пользователи - владельцы электромобилей (в городе и на трассах) и операторы такси/каршеринга
В интервью заказчик подтвердил, что станции размещают стихийно, без учета спроса, и что решение это строить там, где высокий спрос и низкое предложение
В проекте есть ограничения - сроки до конца семестра, только бесплатные сервисы, локальные вычисления
Задача: помоги заполнить документ requirements.md. Мне нужно 5 функциональных требований (FR) с приоритетами по MoSCoW; минимум 4 нефункциональных требования (NFR) с измеримыми порогами (производительность, удобство, совместимость, воспроизводимость); минимум 3 требования к данным (DR): полнота, точность, актуальность, лицензия; список из 3-5 открытых вопросов к заказчику, которые возникли при составлении требований
Формат: таблицы Markdown, каждое требование должно быть проверяемым, не добавляй лишнего, строго по нашему проекту
```
